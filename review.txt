# Аудит по симптому: бекенд отдаёт access token на ~15 мин, но при заходе на сайт
# пользователя снова кидает на /auth/login. Ниже — что в коде может это вызывать
# и что проверить/починить (решение — на усмотрение).

src/api/index.ts:5-8
  access token в localStorage, refresh token — httpOnly cookie (withCredentials: true).
  Если фронт и API на разных origin (localhost:5173 vs api.*), cookie может не
  сохраняться или не уходить на POST /auth/refresh → 401 → redirectToLogin().
  Проверить в DevTools: Set-Cookie после login, cookie на refresh, CORS
  (Allow-Credentials + конкретный Allow-Origin, не *), SameSite/Secure/Domain на беке.

src/api/index.ts:12-24
  refresh только реактивно — после первого 401 на любом axios-запросе. При открытии
  /dashboard с уже протухшим access token сразу цепочка 401 → refresh → fail → login.
  Нет проактивного refresh при старте приложения / перед первым запросом.

src/api/index.ts:27-29
  redirectToLogin() делает window.location.href = '/auth/login' (hard reload).
  Любой провал refresh (нет cookie, неверный ответ, сеть) = мгновенный выход.

src/api/index.ts:47-50
  Если сам POST /auth/refresh вернул 401 — access_token удаляется и редирект на login
  без повторной попытки. Ожидаемо, но при «мигающей» cookie выглядит как вечный logout.

src/api/index.ts:52
  originalRequest._retry без типизации — при ошибках в interceptor сложнее отлаживать
  бесконечные retry (см. также комментарий выше про AxiosRequestConfig extends).

src/utils/authTokens.ts:2-9
  persistAuthTokensFromEnvelope ждёт data.accessToken или data.access_token.
  Если бекенд на login/refresh отдаёт другое поле — токен не попадёт в localStorage,
  первый же запрос на dashboard даст 401. Сверить формат с OpenAPI (api-1.json).

src/utils/authFetch.ts:1-4
  Логин/register/2FA идут через fetch + credentials, не через axios interceptor.
  Cookie с refresh при login зависит только от ответа бекенда и браузера, не от FE-логики.
  edupage/connect (см. api/integrations/edupage.ts) при 401 не получит auto-refresh.

src/router/index.ts:114-121
  path '/' и catch-all '/*' всегда redirect → /auth/login без проверки access_token.
  Заход на корень сайта выглядит как «выкинуло», даже если токен в localStorage валиден.
  Нужен guard: есть токен (или успешный silent refresh) → /dashboard, иначе → login.

src/router/index.ts:124
  (дублирует смысл) нет navigation guard на защищённые маршруты — только BE через 401.
  UX: можно открыть /dashboard без токена, UI загрузится, потом axios interceptor кинет на login.

src/layouts/DashboardLayout.vue:35-38
  onMounted: fetchUser() fire-and-forget без await; параллельно fetchWorkspaces().
  При протухшем токене несколько 401 почти одновременно — refreshInFlight спасает от
  гонки, но при fail все запросы в итоге ведут на login. Нет «bootstrap» сессии до UI.

src/stores/user.ts:36-39
  fetchUser() при ошибке только user=null, loaded=false — редирект не здесь, а в axios.
  Пользователь может кратко видеть dashboard shell до срабатывания interceptor.

vite.config.ts:17-26
  Нет dev proxy на API — при локальной разработке cross-origin cookie частая причина
  «работает сразу после login, после F5 или через 15 мин — на login». Вариант: proxy
  /api → бекенд, единый origin для cookie (или починить CORS+cookie на беке).
